# LifeLoop

목표를 선행지표로, 선행지표를 루틴으로, 배운 것을 내 말로.

혼자 쓰는 설치형 웹앱(PWA)이다. **계정이 없다.** 기록은 기기의 `localStorage` 에 있고,
앱은 항상 그것으로 먼저 돈다. 여러 기기에서 보고 싶을 때만 동기화를 켠다(아래 참고).

## 왜 이렇게 만들었나

자기계발 앱이 실패하는 지점은 기능 부족이 아니다.

1. **입력 마찰** — 기록에 하루 10분이 들면 2주 안에 그만둔다. 그래서 일상 기록은 탭 한 번이다.
2. **"한 척"의 기록** — "3시간 공부함"은 공부했다는 증거가 아니다. 그래서 공부·독서
   세션에는 하루 한 개, 배운 것을 내 말로 설명한 파인만 노트를 남긴다.

## 구조

```
목표 (통제 못 함)      "에너지관리기사 실기 합격"     D-67
 └ 선행지표 (통제 함)   "주 5회 기출 세션"            ← 점수를 매기는 대상
    └ 루틴             "저녁 먹고 나면 → 기출 20문항"  (최소: 5문항)
       └ 세션          타이머 32분 / 탭 한 번
          └ 파인만 노트  "공기비가 크면 왜 손해인가"
             └ 구멍     "최적 공기비 계산이 막힘"      → 다음 세션 주제로 환류
                └ 복습  가린 채 다시 설명하기
```

구멍이 다시 세션으로 돌아오면서 고리가 닫힌다. 그게 이 앱의 전부다.

접목한 것: 구현 의도, 2분 규칙(최소 버전), never miss twice, don't break the chain,
4DX 선행지표, 파인만 기법, 인출 연습, 간격 반복, GTD 주간 회고.

뺀 것: 포인트·아바타 게이미피케이션, 리더보드, 소셜, AI 코치, 감정 일기, 푸시 알림.

## 쓰기

브라우저로 열고 홈 화면에 추가하면 끝이다. 설치 후에는 비행기 모드에서도 동작한다.

### 기출 문항 연결 (선택)

`노트 → 기출 문항 가져오기`에서 회차 JSON 파일을 고른다. 문항은 **이 기기에만**
저장되고 저장소에는 포함되지 않는다. 기대하는 형식:

```json
{
  "year": 2023, "round": 1,
  "questions": [
    { "id": "2023-1-01", "no": 1, "type": "계산", "topic": "연소",
      "question": "...", "given": ["..."], "answer": ["..."], "solution": "..." }
  ]
}
```

노트에는 문제 전문이 아니라 **출처만** 붙는다(`2023년 1회 2번 · 연소`).
공유할 때도 기본적으로 내 설명만 나간다 — 남의 문제를 퍼나르는 도구가 아니다.

## 개발

빌드 단계도 의존성도 없다. 정적 파일을 그대로 서빙하면 된다.

```sh
node selftest.mjs          # 자체 점검 26개
python -m http.server 8123 # 아무 정적 서버나
```

`selftest.mjs`는 날짜 계산, 간격 반복 사다리, 연속 기록/결석, 선행지표 집계,
문항 가져오기 검증, 공유 마크다운을 검사한다. 프레임워크는 쓰지 않는다.

## 기기 간 동기화

`주간` 화면의 `기기 간 동기화`. 한 기기에서 **새 코드 만들기** → **코드 복사** →
다른 기기에서 붙여넣고 **연결**. 로그인은 없고 32자 코드가 곧 열쇠다.
양쪽에 있던 기록은 합쳐진다.

자동으로 맞추는 때: 앱을 열 때, 다른 앱에 갔다 돌아올 때, 인터넷이 다시 연결될 때,
그리고 무엇이든 기록했을 때(1.5초 묶어서 한 번).

### 구조

서버(Supabase)에는 동기화 코드마다 상태 JSON 하나를 통째로 둔다.
동기화는 받고 → `js/merge.js` 로 합치고 → 올린다.

- 합치는 규칙은 하나다. **같은 항목이면 나중에 손댄 쪽, 다른 항목이면 둘 다 남긴다.**
- 어느 쪽이 최신인지 가리려고 `save()` 가 저장 직전에 **바뀐 항목에만** `updatedAt` 을 찍는다.
  화면 곳곳에서 객체를 직접 고치므로 호출부마다 찍게 하면 빠뜨린다. 한 곳에서 끝낸다.
- 지운 항목은 `state.deleted` 에 id 와 시각을 남긴다. 이게 없으면 한쪽에서 지운 노트가
  다른 기기와 맞출 때 되살아난다. 지운 뒤에 다른 기기에서 고친 항목은 살린다. 표시는 180일 뒤 버린다.
- 두 기기가 동시에 올리면 버전 확인으로 늦은 쪽이 409 를 받고, 다시 받아 합친 뒤 올린다.
- 테이블은 RLS 를 켜고 정책을 두지 않았다. 공개 키로는 `sync_pull` / `sync_push` 두 함수만 부를 수 있다.
  코드는 SHA-256 해시로만 저장한다. `js/sync.js` 의 publishable 키는 브라우저에 두라고 만든 공개 키다.

**기출 문항은 동기화하지 않는다.** 용량이 크고 불변이며, 비공개 자료라 서버에 둘 이유가 없다.
기기마다 파일로 한 번 가져오면 된다.

Supabase 프로젝트는 energy-exam 과 같은 것을 쓴다(무료 플랜은 활성 프로젝트 2개까지).
코드가 섞이지 않도록 해시에 앱 이름을 섞는다 — 같은 코드 문자열을 두 앱에서 써도 서로 닿지 않는다.

### 알려진 한계

- 무료 플랜은 일주일 동안 요청이 없으면 프로젝트를 일시정지한다. 그동안은 동기화만 멈추고
  앱은 그대로 동작한다. 대시보드에서 Restore 하면 다시 된다.
- 코드를 아는 사람은 기록을 볼 수 있다. 남에게 보내지 않는다.
