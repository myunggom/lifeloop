# LifeLoop 기획안

작성일: 2026-09-15
상태: 확정 (1차 구현 대상)

---

## 1. 한 줄 정의

**목표를 선행지표로 바꾸고, 선행지표를 루틴으로 쪼개고, 루틴에서 나온 이해를 파인만 노트로 남겨 복습까지 돌리는 개인용 설치형 웹앱.**

혼자 쓰는 도구다. 계정도 서버도 없다. 데이터는 내 폰 안에만 있다.

---

## 2. 해결하려는 문제

일반적인 자기계발 앱이 실패하는 지점은 기능 부족이 아니라 두 가지다.

1. **입력 마찰** — 기록에 하루 10분이 들면 2주 안에 그만둔다.
2. **"한 척"의 기록** — "3시간 공부함"은 공부했다는 증거가 아니다. 시간만 재는 앱은
   성실함의 착시를 만들어내고, 정작 이해했는지는 아무도 묻지 않는다.

LifeLoop은 이 둘을 각각 이렇게 친다.

- 일상 기록은 **탭 한 번(10초)** 으로 끝난다.
- 공부·독서 세션에 한해 하루 **최대 1개**의 파인만 노트를 남긴다. 시간이 아니라
  "설명할 수 있는가"가 기록된다.

---

## 3. 뼈대 — 4DX 구조

목표는 내가 통제할 수 없다. 통제할 수 있는 건 목표를 움직이는 행동이다.
그래서 추적 대상은 목표가 아니라 **선행지표**다.

```
목표 (후행지표)        "에너지관리기사 필기 합격"          D-167
 └ 선행지표            "주 5회 기출 세션"                  ← 점수를 매기는 대상
    └ 루틴             "저녁 먹고 나면 → 기출 20문항"      (최소: 5문항)
       └ 세션          타이머 32분 / 탭 한 번
          └ 파인만 노트  "엔트로피가 왜 항상 증가하나"      (공부·독서 루틴만)
             └ 구멍     "카르노 효율 유도가 막힘"           → 다음 세션 주제로 환류
                └ 복습  3일 뒤 설명 가리고 다시 말하기
```

마지막 두 단계가 다시 세션으로 돌아오면서 **고리가 닫힌다.** 이것이 이 앱의 핵심이다.

## 4. 접목한 검증된 기법과 그 구현 위치

| 기법 | 이 앱에서의 구현 |
|---|---|
| **구현 의도** (Gollwitzer) | 루틴은 반드시 `[언제/어디서] → [무엇]` 형식으로만 저장. 트리거 없는 루틴은 만들 수 없다 |
| **최소 실행 단위 (2분 규칙)** | 루틴마다 "죽어도 이건 한다" 최소 버전 필수 입력. 최소만 해도 연속 기록 유지 |
| **Never miss twice** | 1회 결석은 표시하지 않음. 2회 연속에서만 경고. 일반 트래커가 사람을 이탈시키는 지점을 막는다 |
| **Don't break the chain** | 주간 화면의 12주 잔디밭 |
| **진전의 원리** (Amabile) | 선행지표 주간 달성 바 + 목표 D-day. 작은 전진의 가시화 |
| **파인만 기법** | 개념 → 쉬운 말 설명 → 막힌 곳 표시 → 자기 평가 4단계 |
| **인출 연습** | 복습 시 이전 설명을 **가린 채** 다시 쓰게 하고, 그 후 나란히 비교 |
| **간격 반복** | 자기 평가에 따라 1일 / 3일 / 7→16→35일 |
| **주간 회고** (GTD) | 일요일 3문항: 유지할 것 / 버릴 것 / 다음 주 한 가지 |

### 의도적으로 뺀 것

포인트·코인·아바타 게이미피케이션, 리더보드, 소셜 공유, AI 코치 챗봇, 감정 일기,
푸시 알림. 혼자 쓰는 앱에서 이것들은 만드는 데 며칠 쓰고 일주일 뒤 안 보게 된다.
알림이 필요하면 폰 기본 알람이 이미 더 잘한다.

## 5. 파인만 노트 상세

### 범위 제한

`study`(공부) 또는 `read`(독서) 태그가 붙은 루틴에서만, **하루 최대 1개**.

상한은 제약이 아니라 기능이다. 하루 1개면 한 달 30개 — 자격증 한 과목 분량이다.
상한이 있어야 "오늘 건질 개념 하나"를 고르게 되고, 고르는 행위 자체가 질을 올린다.

### 작성 4단계

1. **개념 한 줄** — "엔트로피가 왜 항상 증가하나"
2. **중학생에게 설명하듯** — 큰 입력창 하나.
   폰 키보드의 받아쓰기(마이크) 버튼으로 **말해서 입력**하는 것이 기본 동선이다.
   파인만 기법의 원형이 "말로 설명하기"이므로 음성이 오히려 정석이고,
   OS 기본 받아쓰기를 쓰면 우리가 구현할 것이 없다.
3. **막힌 곳 표시** — 설명하다 막히면 `여기 모르겠음` 버튼 → 그 지점이 **구멍**으로 저장.
   이 기능의 진짜 산출물은 설명이 아니라 구멍이다.
4. **자기 평가** — 🤔 막막함 / 😐 어설픔 / 😎 설명됨

비유(analogy) 칸은 선택. 비워도 재촉하지 않는다.

### 구멍이 만드는 고리

- 미해결 구멍이 **오늘 화면 상단 배너**에 뜬다.
- 공부 루틴 세션을 시작하면 **"오늘은 이 구멍부터?"** 를 먼저 제안한다.
- 구멍을 메우면 해당 노트를 다시 설명하고 해결 처리한다.

### 복습 (1차 포함)

노트는 쓰고 끝나면 절반이다. 며칠 뒤 다시 띄우되 **이전 설명을 가린 채** 재작성하게 한다.
제출 후에야 예전 설명과 나란히 보여준다.

간격은 자기 평가 기준 고정 배열:

- 🤔 막막함 → 1일 뒤
- 😐 어설픔 → 3일 뒤
- 😎 설명됨 → 7일 → 16일 → 35일 → 75일

> SM-2 같은 본격 간격 반복 알고리즘은 하루 1개 생성 속도에서 고정 배열과 차이가 없다.
> 노트가 300개를 넘어가면 그때 교체한다. (코드에 `ponytail:` 표시)

### 독서

같은 노트 구조에 출처를 `책 제목 + 페이지`로 잡는다. 책 단위 뷰에서
"이 책에서 건진 개념 N개"를 모아 보고, 완독 후 그 개념들을 **한 문단으로 잇는 것**이
책 단위 파인만이 된다. 독후감을 새로 쓰라고 하지 않고 이미 있는 조각을 잇게 한다.

### 선행지표로서의 노트

선행지표 단위는 `세션 수` / `분` / **`노트 수`** 중 선택할 수 있다.
"주 3개 개념 설명하기"를 선행지표로 걸면, 시간이 아니라 이해가 점수 대상이 된다.
시간만 재는 앱이 못 하는 지점이다.

## 6. 화면 구성 (폰 세로, 하단 탭 5개)

### 오늘

- 상단 배너: `복습 3개` · `미해결 구멍 2개` (있을 때만)
- 오늘 요일의 루틴 카드
  - 카드 본문: `저녁 먹고 나면` → `기출 20문항` / 최소: 5문항
  - 버튼: **완료** · **최소만** · **타이머**
  - 2회 연속 결석 시에만 카드에 경고 표시
- 공부·독서 루틴을 완료하면 **"오늘 개념 하나 정리?"** 를 한 번 제안 (거절 가능)

### 목표

목표 목록 + D-day + 선행지표별 이번 주 달성 바. 목표/선행지표/루틴 추가·수정.

### 노트

노트 목록(개념 · 자신감 · 출처 · 미해결 구멍 수), 새 노트 작성, 책별 묶어보기.

### 복습

오늘 복습할 노트를 한 장씩. 설명 가림 → 재작성 → 비교 → 재평가 → 다음 간격 계산.

### 주간

12주 잔디밭, 선행지표 주간 달성률, 회고 3문항, 데이터 내보내기/가져오기.

## 7. 기술 설계

### 스택

**의존성 0개. 빌드 단계 없음.** 순수 HTML + CSS + ES 모듈.

이 규모(화면 5개, 데이터 로컬)에서 React/Vite를 얹으면 얻는 것보다 관리 비용이 크다.
전체 재렌더 방식으로 충분하고, 입력창은 비제어(uncontrolled)로 두어 커서 튐을 피한다.

### 저장

`localStorage` 단일 JSON 키.

> `ponytail:` localStorage는 약 5MB 상한이다. 노트 수천 개까지는 문제없다.
> 초과 조짐이 보이면 IndexedDB(idb-keyval)로 옮긴다. 스키마는 그대로 쓸 수 있다.

서버가 없으므로 계정·인증·개인정보 전송이 전혀 없다. 데이터 유출 경로 자체가 없다.
대신 폰을 잃으면 데이터도 사라지므로 **JSON 내보내기/가져오기**를 1차에 포함한다.

### 타이머

화면이 꺼지면 JS가 멈추므로 초 단위 카운트를 신뢰할 수 없다.
**시작 시각(`Date.now()`)만 저장하고 종료 시 차이를 계산**한다.

### PWA

`manifest.webmanifest` + 서비스워커(앱 셸 cache-first).
설치 후 비행기 모드에서도 완전히 동작한다.

### 데이터 모델

```js
{
  version: 1,
  goals:    [{ id, title, deadline, archived,
               leads: [{ id, title, unit:'session'|'minute'|'note', target }] }],
  routines: [{ id, goalId, leadId, cue, action, minimum,
               tag:'study'|'read'|'other', days:[0..6], archived }],
  sessions: [{ id, routineId, date, minutes, level:'full'|'min', noteId }],
  notes:    [{ id, goalId, routineId, sessionId, date,
               source:{ kind:'study'|'book', title, locator },
               concept, explanation, analogy,
               gaps:[{ id, text, resolved }],
               confidence: 1|2|3,
               reviews:[{ date, explanation, confidence }],
               nextReviewAt }],
  weekly:   [{ week, keep, drop, next }]
}
```

## 8. 성공 기준

1. 평일 기록에 걸리는 시간이 **하루 10초 이내** (루틴 카드 탭).
2. 비행기 모드에서 앱이 완전히 동작한다.
3. 노트 작성이 **3분 이내**에 끝난다.
4. 4주 뒤에도 쓰고 있다. — 다른 어떤 지표보다 이게 유일하게 중요하다.

## 9. 범위 밖 (2차 이후)

- 기기 간 동기화 (Supabase). 필요해지면 스키마 그대로 올린다.
- 누적 데이터 기반 회고 요약 (노트 3개월치가 쌓인 뒤)
- SM-2 간격 반복 교체 (노트 300개 초과 시)
- 다른 사람과 함께 쓰기 — 현재 설계에 없고, 넣으려면 별도 기획이 필요하다.
